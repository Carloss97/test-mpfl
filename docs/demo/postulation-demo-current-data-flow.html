Plan recomendado replanteado

1. Cerrar experiencia local end-to-endImplementar Fase F: reporte final visual, descargas y drawer. Esto convierte lo ya probado en una demo mostrable.
2. Asegurar demo confiableFixture sintético, QA visual, smoke manual con/sin cámara, runbook. Objetivo: no depender de condiciones de sala.
3. Diseñar contrato HR antes de backendDefinir JSON/API, permisos, retención y borrado. No construir dashboard sin contrato de datos estable.
4. Añadir CV/rol como módulo aisladoPrimero schema + parsing local/fake, luego LLM server opcional. Mantener separación entre evidencia conductual y CV.
5. Construir dashboard recruiter MVPLista de candidatos, detalle, reporte, filtros, descargas, caveats y governance visible. Sin ranking automático.
6. Endurecer para pilotoSeguridad, privacy/legal, device/browser QA, protocolo piloto y validación psicométrica inicial.

Orden recomendado: no saltar directo al servidor/LLM. Primero hacer excelente el reporte local y la demo reproducible; luego diseñar contrato HR; recién después implementar backend/dashboard.
